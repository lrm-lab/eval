### 首页历史分差

`GET /api/v1/home/evaluation-map` 提供可见题库、组合、批次数与同代最新批次。客户端用 `POST /api/v1/compare/history` 批量取得分差，保留项目、Scope、撤回与发布代检查。详情的前后批次和逐题链接使用实际批次 ID、发布代及评分协议。

- 首选现有可验证运行配置和共同有效题的历史分差。运行配置无法核实一致时，已批准的同题批次可作明确标记的参考。区分真实分差、有效 0 分、运行快照、缺少记录与无权限。
- 现行验收样例包括 已审阅的 DeepSWE Codex「Chat → Responses」配置对照在 3 道共同有效题上由 0 到 1 道得分，变化为 +33.33 pp。Pi 后批尚未完成，运行快照在 2 道共同有效题上由 1 到 0 道得分，变化为 −50.00 pp。发布代漂移、撤回和权限变化后不得复用旧的分差。 [真实 Harbor 对照](https://github.com/lrm-lab/eval/commit/70af1bb)
- 热力图更新后，验收同时核对桌面与 390px 窗口的配色、详情文案、搜索结果、真实分母与逐题链接。查看位置与分组选项在刷新后可恢复。 [热力图详设](02-pages/01-home-leaderboard-and-profiles.md)

### 诊断效率图的口径

横轴可以是耗时、总 Token 或推理 Token，纵轴是有效评分。前沿点在当前筛选中不存在资源用量更少且得分至少相同，或资源用量相同且得分更高的其他点。批次必须有完整横轴覆盖才参与前沿。已观测的推理 Token 为 0 可以与非零输入、输出 Token 并存。跨题库和单题批次的点仅表示各自样本成绩，解释时须查看题库、分母和横轴覆盖。 [诊断详设](02-pages/05-diagnostics-and-behavior.md)

## 加载优化和首评

下列改动已随 197 发布。持续验收使用同一隔离索引，记录首屏、接口、冷开和重复打开的各阶段耗时。

| 改动 | 行为与验收边界 | 任务 |
| --- | --- | --- |
| 热力图首次有效分 | 同一可识别组合的第一笔已发布有效分，以 0 为起始基线。正分标红，0 分持平，低于 0 分标绿，未评分显示原因。存在可核实的真实前次时优先展示实际分差。未计分、权限失败、发布代不匹配和组合身份未登记各自保留原因。首评详情明确写出起始基线。 | #eval:#81 |
| ATIF 与来源审批提速 | 同一记录对比首次打开与再次打开，分别量正文首字节、渲染和来源路径耗时。测试来源规则重载和撤回、权限、同代摘要及软链接路径边界。对来源路径的并行核验保留顺序与请求级版本检查；清册换版时重新判断，反复换版返回可重试错误。ATIF 仅组装和脱敏当前页，整份证据仍校验摘要。 | #eval:#80、#83 |
| 热力图和常用图表加载 | 页面按需获取图表资源，首页优先显示可见板块。进入诊断时并行加载页面和图表渲染器，模块就绪即绘图。计时分别记录首次色块、涨跌、对比图、诊断图、接口首字节和资源体积，覆盖冷开、重复打开及版本切换后旧标签页。记录 197 的制品版本和样本。 | #eval:#82、#83、#85 |
| 执行页分段显示 | 先显示页面和已可读取的作业区，执行配置到达后开启相应操作；选题库时加载该题库所需的任务信息，并保留 Runner 就绪检查及服务端提交守卫。验收验证缺失、延迟、失败和 390px 页面。 | #eval:#84 |

首页目录提供 `scored_run_count` 及 `has_scored_history_peer`。仅在访问范围内能够确认首评时，由已发布分数直接渲染起始基线；存在可用历史时按原条件查询 `/api/v1/compare/history`。

执行页先调用 `GET /api/v1/execution/capabilities?discover_tasks=false` 加载题库登记，再用 `?suite_id=<id>` 查询所选题库。省略参数继续返回完整能力。作业和通知独立加载，预检和提交仍由服务器核验。 [首评与执行拆分](https://github.com/lrm-lab/eval/commit/7783a0c) · [审批与 ATIF](https://github.com/lrm-lab/eval/commit/e81dbd9)
